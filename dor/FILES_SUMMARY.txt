🗄️ DATABASE CHANGES (SUPABASE)
─────────────────────────────────────────────────────────────────────────────────

NEW TABLES:
──────────

1. doctors (Médicos)
   Fields: id, username, name, specialty, clinic_name, address, phone, email, crm, notes
   Indexes: (username), (name)
   FK: users → (username)

2. appointments (Consultas)
   Fields: id, username, doctor_id, appointment_date, appointment_time, reason,
           symptoms, diagnosis, follow_up_date, follow_up_type, status
   Indexes: (username), (doctor_id), (appointment_date)
   FKs: users → (username), doctors → (doctor_id)

3. prescriptions (Receitas)
   Fields: id, username, doctor_id, appointment_id, prescription_date, medication_name,
           dosage, form, quantity, usage_frequency, usage_timing, usage_instructions,
           indication, start_date, end_date, adherence_status, efficacy_notes,
           helps_prevent, triggers_migraines, (+ 10 more)
   Indexes: (username), (doctor_id), (medication_name), (date_range)
   FKs: users, doctors, appointments

NEW VIEWS:
──────────

1. active_prescriptions
   - Shows only active/paused prescriptions where end_date >= today

2. prescription_analysis
   - Joins prescriptions with doctors
   - Shows current status (Em uso / Ativa / Descontinuada)

ROW-LEVEL SECURITY:
───────────────────

12 policies configured:
- Users can select/insert/update/delete only THEIR OWN data
- Applied to: doctors, appointments, prescriptions
- Impossible to view other users' data even with direct SQL
